# Архитектура прувера

> **Статус:** Завершён
> **Источник:** `14-prover-architecture.md`
> **Этап:** 5.6

## Краткое описание

Прувер МТС (aprover) — **вычислитель различений форм**, где доказательство = резолюция запроса по форме в асети связей. Это принципиально иной фундамент, чем у классических пруверов (Rocq/Lean).

---

## 1. Онтологическая природа прувера

### Прувер МТС vs классические пруверы

| Аспект | Классический прувер (Rocq/Lean) | Прувер МТС |
|--------|--------------------------------|------------|
| Вход | Абстрактное синтаксическое дерево (AST) | Запрос по форме (сам по себе связь) |
| Ядро | Проверяет вывод в логике (→, ∀, ∃) | Резолвирует запрос в асети связей |
| Семантика | Внешняя (модели, категории) | Внутренняя (асеть = модель) |
| Типизация | Внешняя дисциплина | Структурная форма связи |
| Рекурсия | Дополнительный механизм (μ/ν) | Свойство асети (guarded по природе) |

**Ключевое отличие:** Классические пруверы опираются на внешнюю логику. Прувер МТС не опирается ни на какую логику — логика *возникает* как структура запросов в асети.

## 2. Архитектурная схема

### Поток данных

```
┌─────────────────────────────────────────────────────┐
│  Интерфейс ввода (три нотации)                      │
│  • Формальная: файлы .mtl                           │
│  • Строковые ачисла: файлы .astr                    │
│  • Четверичные ачисла: файлы .anum                  │
└───────────────┬─────────────────────────────────────┘
                ↓
┌─────────────────────────────────────────────────────┐
│  Лексер + Парсер → запрос по форме                  │
│  (не AST! запрос сам является связью)               │
└───────────────┬─────────────────────────────────────┘
                ↓
┌─────────────────────────────────────────────────────┐
│  Нормализатор                                       │
│  • Десахаризация (!!x → x, !(♂x) → x♀)             │
│  • Канонизация выражений                            │
└───────────────┬─────────────────────────────────────┘
                ↓
┌─────────────────────────────────────────────────────┐
│  Резолютор запросов (prover.ts)                     │
│  • Структурная унификация                           │
│  • Применение аксиом                                │
│  • Modus Ponens                                     │
│  • Трассировка доказательства                       │
└───────────────┬─────────────────────────────────────┘
                ↓
┌─────────────────────────────────────────────────────┐
│  Асеть связей (единая модель)                       │
│  • Все связи существуют априори                     │
│  • Резолюция = различение формы                     │
│  • Нет «построения» — только «нахождение»           │
└───────────────┬─────────────────────────────────────┘
                ↓
┌─────────────────────────────────────────────────────┐
│  Результат: ProofResult                             │
│  • success: boolean                                 │
│  • proofSteps: детальные шаги доказательства        │
│  • appliedAxioms: использованные аксиомы            │
│  • hints: подсказки при неудаче                     │
└─────────────────────────────────────────────────────┘
```

## 4. Состояние прувера

### Структура ProverState

```typescript
interface ProverState {
  /** Встроенные аксиомы как (P → Q) связи */
  axioms: ASTNode[]

  /** Пользовательские определения: s : F */
  definitions: Map<string, ASTNode>

  /** Доказанные факты (канонические строки) */
  facts: Set<string>

  /** Доказанные факты как AST-узлы для Modus Ponens */
  provenFacts: ASTNode[]

  /** Доказанные равенства для транзитивности/конгруэнции */
  provenEqualities: ProvenEquality[]

  /** Доказанные импликации для Modus Ponens */
  provenImplications: ProvenImplication[]

  /** Трассировка для отладки */
  trace: string[]
}
```

### Инициализация состояния

Функция `createProverState()` создаёт начальное состояние с:

| Аксиома | Инициализация |
|---------|---------------|
| А0 | Мета-аксиома, обрабатывается специально |
| А1 | `facts.add('(x=x)')` — рефлексивность |
| А4 | `definitions.set('∞', '∞ → ∞')` — акорень |
| А7 | `addAxiomEq('!∞', '∞')` — инверсия акорня |
| А8 | `definitions.set('1', '♂∞ → ∞♀')` — единица смысла |
| А9 | `definitions.set('0', '!1')` — нуль смысла |
| А10 | `definitions.set('[', '♂∞')`, `definitions.set(']', '∞♀')` — абиты |

## 5. Структурная типизация через формы

В МТС нет «типов» как отдельной категории. Есть **формы связей**:

```
Форма самозамыкания начала: ♂x = (♂x → x)
Форма самозамыкания конца:  x♀ = (x → x♀)
Форма полного самозамыкания: ∞ = (∞ → ∞)
Форма направленной связи:   a → b
```

**Типизация = распознавание формы**:

| Запрос | Резолюция | Форма |
|--------|-----------|-------|
| `♂x` | Связь `y = y → x` | Самозамыкание начала |
| `1` | Связь `♂∞ → ∞♀` | Направленная связь |
| `0` | Связь `∞♀ → ♂∞` | Инверсия связи |

Нет проверки типов — есть **успешная/неуспешная резолюция запроса**. Если запрос не находит соответствия в асети — это не «ошибка типизации», а **факт отсутствия связи данной формы**.

---

## 6. Guarded recursion как встроенное свойство

Рекурсивные определения в МТС работают без μ-оператора, потому что:

1. **Асеть содержит все формы** (включая рекурсивные)
2. **Конструктор `→` ограждает рекурсию**:
   ```
   ♂x : (♂x → x)   // ♂x под → — ограждено
   ```
3. **Резолюция находит фиксированную точку** в асети

**Нет «построения» рекурсивной структуры** — есть **нахождение** уже существующей формы.

## 7. Процесс верификации

### Функция verify()

```typescript
function verify(node: ASTNode, state: ProverState): ProofResult
```

**Алгоритм:**

1. **Нормализация** — применение правил десахаризации
2. **Диспетчеризация по типу выражения**:
   - `EqExpr` → `checkEquality()`
   - `NeqExpr` → `checkInequality()`
   - `DefExpr` → регистрация определения
   - `LinkExpr` → регистрация импликации + Modus Ponens
3. **Возврат результата** с шагами и использованными аксиомами

### Функция checkEquality()

```typescript
function checkEquality(left: ASTNode, right: ASTNode, state: ProverState): ProofResult
```

**Стратегии проверки равенства:**

| Порядок | Стратегия | Аксиома |
|---------|-----------|---------|
| 1 | Структурное сравнение | А1 (рефлексивность) |
| 2 | Раскрытие определений | А0 |
| 3 | Унификация | А1 |
| 4 | Применение ♂x = (♂x → x) | А5 |
| 5 | Применение x♀ = (x → x♀) | А6 |
| 6 | Рекурсивное свёртывание ♂ | А5 |
| 7 | Рекурсивное свёртывание ♀ | А6 |
| 8 | Свёртывание ∞ | А4 |
| 9 | Ранее доказанные равенства | А1 (симметрия) |
| 10 | Транзитивность | А1 |
| 11 | Конгруэнция | А2 |

## 8. Сериализация через ачисла

В МТС сериализация — не внешний механизм, а часть онтологии:

```
Ачисло = последовательность абитов = запрос по форме = связь
```

### Три способа адресации одной связи

| Нотация | Адресация | Пример |
|---------|-----------|--------|
| Формальная | Паттерн формы | `♂∞ → ∞♀` |
| Строковое ачисло | UTF-8 символы | `"1"` |
| Четверичное ачисло | Абиты `[ ] 1 0` | `[1]` |

Все представления **одновременно являются связями** в асети.

---

## 9. Почему не требуется внешняя семантика

### Классический подход (разрыв синтаксис-семантика)

```
Синтаксис (формулы) → интерпретация → Семантика (модель)
```

Требует внешнего обоснования: «почему эта модель адекватна?»

### Подход МТС (замкнутая онтология)

```
Запрос по форме → резолюция в асети → Связь (результат)
```

**Асеть связей — это одновременно:**
- Синтаксис (формы запросов)
- Семантика (пространство резолюции)
- Вычислительная модель (процесс различения)

Нет «интерпретации» — есть **акт различения формы в том же онтологическом поле**.

## 10. Реализация в коде

### Основные экспортируемые функции

| Функция | Файл | Назначение |
|---------|------|------------|
| `createProverState()` | `prover.ts:223` | Создание начального состояния |
| `verify()` | `prover.ts:1703` | Верификация выражения |
| `checkEquality()` | `prover.ts:1194` | Проверка равенства |
| `unify()` | `prover.ts:294` | Структурная унификация |
| `tryModusPonens()` | `prover.ts:1052` | Применение MP |
| `addProvenFact()` | `prover.ts:998` | Добавление доказанного факта |
| `addProvenEquality()` | `prover.ts:967` | Добавление доказанного равенства |

### Пример использования

```typescript
import { createProverState, verify } from './src/core/prover'
import { parseExpr } from './src/core/parser'

// Создание состояния
const state = createProverState()

// Парсинг выражения
const expr = parseExpr('∞ = ∞ → ∞')

// Верификация
const result = verify(expr, state)

if (result.success) {
  console.log('Доказано!')
  console.log('Аксиомы:', result.appliedAxioms?.map(a => a.id))
  console.log('Шаги:', result.proofSteps)
} else {
  console.log('Не доказано')
  console.log('Подсказки:', result.hints)
}
```

## 11. Расширяемость

### Добавление новых аксиом

Новые аксиомы добавляются в `AXIOMS` и `createProverState()`:

```typescript
// В AXIOMS добавить описание
A12: {
  id: 'A12',
  name: 'Новая аксиома',
  formula: '...',
  description: '...',
}

// В createProverState() добавить обработку
state.definitions.set('новый_символ', parseAndNormalize('форма'))
```

### Добавление новых стратегий проверки

В `checkEquality()` добавить новую стратегию перед генерацией подсказок.
