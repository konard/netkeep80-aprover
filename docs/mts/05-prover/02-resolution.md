# Алгоритм резолюции

> **Статус:** Завершён
> **Источник:** `10-resolution-algorithm.md`
> **Этап:** 5.6

## Краткое описание

Резолюция в МТС — это не вычисление или построение, а **акт различения форм** в онтологически данной асети связей. Связи существуют априори; знаки задают паттерны для их различения.

---

## 1. Онтологический фундамент резолюции

### Три фазы резолюции

```
Вход: последовательность знаков
       ↓
Фаза 1: Лексическая → знак как запрос по форме
       ↓
Фаза 2: Синтаксическая → композиция запросов
       ↓
Фаза 3: Семантическая → поиск в асети связей
       ↓
Выход: связь (результат различения формы)
```

### Ключевые принципы

| Принцип | Описание |
|---------|----------|
| Априорное существование | Связи существуют до резолюции, запрос только выделяет их |
| Знак = связь-запрос | Символ — не метаобозначение, а связь, задающая паттерн |
| Резолюция ≠ вычисление | Нет «построения» — есть нахождение в асети |
| Единственность | Для корректных запросов резолюция даёт единственную связь |

---

## 2. Фаза 1: Лексическая — знак как запрос

Каждый знак формальной нотации — уже связь, определённая своим паттерном:

| Знак | Запрос по форме | Онтологический статус |
|------|-----------------|----------------------|
| `∞` | «Найти связи формы `x = x → x`» | Запрос к полному самозамыканию |
| `♂` | «Найти связи формы `y = y → x` для данного `x`» | Префиксный конструктор самозамыкания начала |
| `♀` | «Найти связи формы `y = x → y` для данного `x`» | Постфиксный конструктор самозамыкания конца |
| `!` | «Инвертировать направление связи» | Оператор дуальности |
| `[` | «Найти связи формы `♂∞`» | Абит начала контекста |
| `]` | «Найти связи формы `∞♀`» | Абит конца контекста |
| `1` | «Найти связи формы `♂∞ → ∞♀`» | Абит истины (единица смысла) |
| `0` | «Найти связи формы `∞♀ → ♂∞`» | Абит лжи (нуль смысла) |

**Важно:** Знак не «обозначает» связь — он *есть* связь-запрос.

## 3. Фаза 2: Синтаксическая — композиция запросов

### Правила группировки

Правила — онтологические принципы композиции, а не метаправила:

| Правило | Пример | Группировка |
|---------|--------|-------------|
| `♂` — правоассоциативный префикс | `♂∞]` | `(♂∞) ]` |
| `♀` — левоассоциативный постфикс | `∞♀[` | `(∞♀) [` |
| `→` — левоассоциативный инфикс | `a → b → c` | `(a → b) → c` |
| Отсутствие оператора ⇒ `→` | `(♂∞) ]` | `(♂∞) → ]` |

### Пример композиции

```
Ввод:     ♂∞]
Разбор:   (♂∞) → ]
Запрос:   «Найти связь с началом формы (♂∞) и концом формы ]»
```

## 4. Фаза 3: Семантическая — резолюция в асети

### Пошаговый пример: резолюция `♂∞]`

**Шаг 1. Резолюция `∞`:**
```
Запрос: «Найти связи формы x = x → x»
Результат: ∞ (по аксиоме А4, единственность гарантирована)
```

**Шаг 2. Резолюция `♂∞`:**
```
Запрос: «Найти связи формы y = y → ∞»
Результат: ♂∞ (по аксиоме А5: ♂∞ = ♂∞ → ∞)
```

**Шаг 3. Резолюция `]`:**
```
Запрос: «Найти связи формы ∞ → ∞♀»
Результат: ∞♀ (по аксиоме А10: ] : ∞♀)
```

**Шаг 4. Резолюция `(♂∞) → ]`:**
```
Запрос: «Найти связь с началом ♂∞ и концом ∞♀»
Результат: (♂∞ → ∞♀) (по аксиоме А3: существование связи)
```

**Итог:**
```
♂∞]  ⇝  (♂∞ → ∞♀)  ⇝  1   (по аксиоме А8)
```

## 5. Структурная унификация

### Функция unify()

```typescript
function unify(a: ASTNode, b: ASTNode, subst: Substitution): Substitution | null
```

Унификация находит подстановку переменных, при которой два выражения становятся идентичными.

### Алгоритм унификации

1. **Применить существующие подстановки** к обоим узлам
2. **Если узлы идентичны** → вернуть текущую подстановку
3. **Если один узел — переменная** → связать переменную (с occurs check)
4. **Если узлы одного типа** → рекурсивно унифицировать компоненты
5. **Иначе** → унификация невозможна (вернуть null)

### Occurs check

Проверка на вхождение переменной в терм предотвращает бесконечные структуры:

```typescript
function occursIn(varName: string, term: ASTNode): boolean
```

**Пример:**
- `unify(x, x → y)` — невозможно, `x` входит в терм

## 6. Применение аксиом

### Порядок применения в checkEquality()

| Приоритет | Аксиома | Функция |
|-----------|---------|---------|
| 1 | А1 (рефлексивность) | Прямое структурное сравнение |
| 2 | А0 (определение) | `expandDefinitions()` |
| 3 | А1 (унификация) | `unify()` |
| 4 | А5 (♂x) | `applyMaleAxiom()` |
| 5 | А6 (x♀) | `applyFemaleAxiom()` |
| 6 | А5 (рекурсивно) | `expandMale()` |
| 7 | А6 (рекурсивно) | `expandFemale()` |
| 8 | А4 (∞) | `collapseInfinity()` |
| 9 | А1 (симметрия) | `checkWithProvenEqualities()` |
| 10 | А1 (транзитивность) | `tryTransitivity()` |
| 11 | А2 (конгруэнция) | `tryCongruence()` |

### Раскрытие определений

```typescript
function expandDefinitions(node: ASTNode, state: ProverState): ASTNode
```

Рекурсивно заменяет идентификаторы их определениями из `state.definitions`.

### Свёртывание рекурсивных форм

**Свёртывание ∞:**
```typescript
function collapseInfinity(node: ASTNode): ASTNode
```
Сворачивает `(∞ → ∞) → ∞`, `((∞ → ∞) → ∞) → ∞` и т.д. в `∞`.

**Свёртывание ♂x:**
```typescript
function expandMale(node: ASTNode): ASTNode
```
Сворачивает `(♂v → v) → v`, `((♂v → v) → v) → v` и т.д. в `♂v`.

**Свёртывание x♀:**
```typescript
function expandFemale(node: ASTNode): ASTNode
```
Сворачивает `v → (v → v♀)`, `v → (v → (v → v♀))` и т.д. в `v♀`.

## 7. Транзитивность и конгруэнция

### Транзитивность (А1)

```
Если доказано (a = b) и (b = c), то доказано (a = c)
```

```typescript
function tryTransitivity(
  left: ASTNode,
  right: ASTNode,
  state: ProverState
): { found: boolean; intermediate?: ASTNode }
```

**Алгоритм:**
1. Для каждого доказанного равенства `(eq1.left = eq1.right)`
2. Проверить, совпадает ли `left` с `eq1.left` или `eq1.right` (симметрия)
3. Если совпадает, искать второе равенство с промежуточным элементом

### Конгруэнция (А2)

```
Если доказано (a = c) и (b = d), то доказано ((a → b) = (c → d))
```

```typescript
function tryCongruence(
  left: ASTNode,
  right: ASTNode,
  state: ProverState
): { found: boolean; leftParts?; rightParts? }
```

**Алгоритм:**
1. Проверить, что оба выражения — `LinkExpr`
2. Извлечь компоненты: `(a → b)` и `(c → d)`
3. Проверить, доказаны ли `(a = c)` и `(b = d)`

## 8. Доказанные равенства

### Структура ProvenEquality

```typescript
interface ProvenEquality {
  left: ASTNode
  right: ASTNode
  normalized: boolean
}
```

### Добавление равенства

```typescript
function addProvenEquality(state: ProverState, left: ASTNode, right: ASTNode): void
```

- Нормализует оба узла
- Проверяет на дублирование (включая симметричный вариант)
- Добавляет в `state.provenEqualities`

### Использование доказанных равенств

```typescript
function checkWithProvenEqualities(
  left: ASTNode,
  right: ASTNode,
  state: ProverState
): { found: boolean; symmetric: boolean }
```

Проверяет, было ли равенство уже доказано (напрямую или по симметрии).

## 9. Подсказки при неудаче

### Структура VerificationHint

```typescript
interface VerificationHint {
  type: 'structural' | 'definition' | 'axiom' | 'suggestion'
  message: string
  relatedAxiom?: AxiomId
}
```

### Генерация подсказок

```typescript
function generateEqualityHints(
  left: ASTNode,
  right: ASTNode,
  expLeft: ASTNode,
  expRight: ASTNode
): VerificationHint[]
```

**Типы подсказок:**

| Условие | Подсказка |
|---------|-----------|
| Разные типы узлов | «Разные типы выражений: X ≠ Y» |
| ♂ и ♀ вместе | «♂ и ♀ дуальны, но не взаимозаменяемы» (А7) |
| Есть ♂ | «Попробуйте А5: ♂x = (♂x → x)» |
| Есть ♀ | «Попробуйте А6: x♀ = (x → x♀)» |
| Есть ∞ | «Попробуйте А4: ∞ = (∞ → ∞)» |
| Оба Link | «Проверьте структуру связей» |

## 10. Отличие от классических пруверов

| Аспект | Rocq/Lean4 | МТС |
|--------|------------|-----|
| Нотация | Внешний синтаксический сахар | Внутренний язык запросов |
| Синтаксический разбор | Преобразование текста в AST | Акт связывания в системе |
| Семантика | Внешняя модель | Асеть связей (онтологически данная) |
| Результат | Терм + тип | Связь в асети |

Резолюция `♂∞]` — это не преобразование текста, а **онтологический акт различения формы** в асети.

## 11. Реализация в коде

### Основные функции резолюции

| Функция | Файл | Назначение |
|---------|------|------------|
| `checkEquality()` | `prover.ts:1194` | Главная функция проверки равенства |
| `unify()` | `prover.ts:294` | Структурная унификация |
| `expandDefinitions()` | `prover.ts:509` | Раскрытие определений |
| `collapseInfinity()` | `prover.ts:616` | Свёртывание ∞-выражений |
| `expandMale()` | `prover.ts:661` | Свёртывание ♂-выражений |
| `expandFemale()` | `prover.ts:712` | Свёртывание ♀-выражений |
| `tryTransitivity()` | `prover.ts:860` | Применение транзитивности |
| `tryCongruence()` | `prover.ts:923` | Применение конгруэнции |
| `generateEqualityHints()` | `prover.ts:751` | Генерация подсказок |

### Пример кода

```typescript
import { checkEquality, createProverState } from './src/core/prover'
import { parseExpr } from './src/core/parser'

const state = createProverState()

// Пример 1: Прямое структурное равенство
const result1 = checkEquality(
  parseExpr('∞'),
  parseExpr('∞'),
  state
)
// result1.success === true, appliedAxioms: [A1]

// Пример 2: Применение аксиомы А4
const result2 = checkEquality(
  parseExpr('∞'),
  parseExpr('∞ → ∞'),
  state
)
// result2.success === true, appliedAxioms: [A4]

// Пример 3: Рекурсивное свёртывание
const result3 = checkEquality(
  parseExpr('(∞ → ∞) → ∞'),
  parseExpr('∞'),
  state
)
// result3.success === true, appliedAxioms: [A4]
```
