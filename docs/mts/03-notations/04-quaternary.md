# Четверичная нотация (.anum)

> **Статус:** Завершён
> **Источники:** `07-three-notations.md`, `08-abits-as-queries.md`, `specification/v0.1.md`
> **Этап:** 5.4

## Назначение

Четверичная (абитовая) нотация — базовая форма сериализации связей для апамяти. Использует минимальный алфавит из ровно четырёх символов (абитов).

| Характеристика | Значение |
|----------------|----------|
| Расширение файлов | `.anum` (Associative NUMber) |
| Алфавит | `0`, `1`, `[`, `]` (ровно 4 символа) |
| Онтологический статус | Базовая сериализация связей в апамяти |
| Область применения | Апамять, вычисления, минимальное представление |

## Абиты — не примитивы, а запросы к формам

В МТС абиты **не являются** элементарными «строительными блоками» вроде битов. Это **запросы по форме** к четырём базовым связям, возникающим в непосредственной окрестности акорня ∞.

| Абит | Запрос к форме | Онтологический смысл |
|------|----------------|----------------------|
| `[`  | `♂∞`           | Начальный смысл: связь, у которой начало самозамкнуто на себя, а конец — акорень |
| `]`  | `∞♀`           | Конечный смысл: связь, у которой начало — акорень, а конец самозамкнут на себя |
| `1`  | `♂∞ -> ∞♀`     | Наличие направленной связи (истина как факт различения) |
| `0`  | `∞♀ -> ♂∞`     | Отсутствие/инверсия связи (ложь как отсутствие различения) |

**Ключевой принцип:** Абит `[` не «кодирует» начало — он **есть** запрос к форме `♂∞`. Когда этот запрос резолвируется в асети связей, результатом становится сама связь `♂∞`. То же для остальных абитов.

## Почему ∞ не является абитом

Акорень ∞ обладает принципиально иным онтологическим статусом:

| Свойство | Абиты (`[`, `]`, `1`, `0`) | Акорень ∞ |
|----------|----------------------------|-----------|
| Природа | Запросы к **частичным** формам самозамыкания | Запрос к **полному** самозамыканию |
| Форма | `♂∞`, `∞♀`, `♂∞ -> ∞♀`, `∞♀ -> ♂∞` | `x = x -> x` |
| Роль в асети | Связи **вокруг** акорня (соседи первого порядка) | Центр асети, условие возможности всех других связей |
| Сериализация | Входят в состав ачисел как элементы | **Не сериализуется** — служит неявной точкой начала |

**Почему ∞ не может быть абитом:**
- Абиты описывают **роли** в акте связывания (начало, конец, наличие, отсутствие)
- ∞ — это **условие возможности** самого различения ролей
- Включение ∞ в ачисло создало бы онтологический парадокс: точка отсчёта стала бы частью отсчитываемого

В ачислах ∞ присутствует **неявно** как маркер начала последовательности: любое ачисло `α` интерпретируется как `∞α` на уровне резолюции запросов.

## Структура асети вокруг акорня

Четыре абита — **единственные** непосредственные соседи акорня в асети:

```
        ♂∞          // абит [
         ↓
         ∞ ←─────── ∞   // акорень (не абит!)
         ↓
        ∞♀          // абит ]

♂∞ -> ∞♀  // абит 1 (стрелка от начала к концу)
∞♀ -> ♂∞  // абит 0 (стрелка от конца к началу)
```

Все остальные связи строятся через композицию этих форм. Поэтому именно они становятся абитами — не по соглашению, а по онтологической необходимости.

## Резолюция `[]` → ∞

Ачисло `[]` — это композиция двух запросов, которая при резолюции восстанавливает акорень:

```
[  → запрос к форме ♂∞  → резолюция: связь ♂∞
]  → запрос к форме ∞♀  → резолюция: связь ∞♀
```

Композиция:

```
[]  ≡  [ -> ]          // ачисло как последовательность запросов
    ≡  (♂∞) -> (∞♀)    // подстановка резолюций запросов
    ≡  ♂∞ -> ∞♀        // упрощение скобок
```

По **теореме о слиянии рекурсий** (`♂♀ = ∞`): композиция форм `♂∞` и `∞♀` через акт связывания восстанавливает полное самозамыкание, то есть резолвируется в `∞`.

**Итог:** `[]` — это **минимальный запрос**, чья резолюция восстанавливает акорень. Это не «кодирование» ∞, а **восстановление** его через композицию двух частичных самозамыканий.

## Почему `[` и `]`, а не `(` и `)`

Круглые скобки в формальной нотации выполняют роль **метаоператора группировки** — они переопределяют порядок композиции запросов, но не являются запросами к формам связей.

| Скобки | Нотация | Роль | Онтологический статус |
|--------|---------|------|----------------------|
| `( )` | Формальная | Группировка приоритета | Метаоператор |
| `[ ]` | Четверичная | Абиты начала/конца | Запросы по форме |

**Коллизия при смешении:**
- В формальной нотации: `(a -> b)` — группировка запросов
- В абитовой нотации: `(` — абит начала контекста (гипотетически)

Квадратные скобки `[` и `]` свободны от этой коллизии и естественно выражают структурные границы контекста в апамяти.

## Вложенные контексты

Поддерживаются вложенные контексты с помощью квадратных скобок:

```
01010001[010100[1001]010]
```

Структура:
- `01010001` — внешняя последовательность абитов
- `[010100[1001]010]` — вложенный контекст
  - `010100` — начало вложенного контекста
  - `[1001]` — глубоко вложенный контекст
  - `010` — конец вложенного контекста

## Формат файла .anum

### Синтаксис (EBNF)

```ebnf
AbitFile  ::= AbitSeq ;
AbitSeq   ::= { AbitAtom } ;
AbitAtom  ::= "0" | "1" | Ctx ;
Ctx       ::= "[" AbitSeq "]" ;
```

### Пример файла

```anum
// Комментарии поддерживаются

// Простые абиты
1
0
[]

// Последовательности
0101
1010

// Вложенные контексты
[01]
01010001[010100[1001]010]
```

### Правила

| Правило | Описание |
|---------|----------|
| Допустимые символы | Только `0`, `1`, `[`, `]` |
| Баланс скобок | `[` и `]` должны быть сбалансированы |
| Комментарии | `//` до конца строки |
| Каждая строка | Отдельное ачисло |

## Конвертация в формальную нотацию

### Алгоритм

1. Валидация структуры (только `0`, `1`, `[`, `]`, баланс скобок)
2. Каждый абит заменяется соответствующей формой МТС
3. Левоассоциативная композиция связей
4. Результат верифицируется прувером

### Таблица соответствия

| Абит | Формальная нотация |
|------|-------------------|
| `[` | `♂∞` |
| `]` | `∞♀` |
| `1` | `(♂∞ -> ∞♀)` |
| `0` | `(∞♀ -> ♂∞)` |

### Примеры конвертации

| Ачисло | Формальная нотация |
|--------|-------------------|
| `1` | `♂∞ -> ∞♀` |
| `0` | `∞♀ -> ♂∞` |
| `[]` | `♂∞ -> ∞♀` ≡ `1` |
| `01` | `((∞♀ -> ♂∞) -> (♂∞ -> ∞♀))` |
| `[01]` | `((♂∞ -> (∞♀ -> ♂∞)) -> ((♂∞ -> ∞♀) -> ∞♀))` |

## Визуализация конвертации

При загрузке `.anum` файла можно включить панель визуализации (кнопка "Show Conv"):

```
┌────────────────────────────────────────────┐
│ Ачисло: [01]                               │
├────────────────────────────────────────────┤
│ Легенда:                                   │
│   [ = ♂∞  (начальный смысл)                │
│   ] = ∞♀  (конечный смысл)                 │
│   1 = ♂∞ -> ∞♀ (истина)                    │
│   0 = ∞♀ -> ♂∞ (ложь)                      │
├────────────────────────────────────────────┤
│ Шаги конвертации:                          │
│   [ → ♂∞                                   │
│   0 → (∞♀ -> ♂∞)                           │
│   1 → (♂∞ -> ∞♀)                           │
│   ] → ∞♀                                   │
├────────────────────────────────────────────┤
│ Результат: ((♂∞ -> (∞♀ -> ♂∞)) -> ...)    │
└────────────────────────────────────────────┘
```

## Практическая сериализация

При сериализации связи в ачисло:

1. Связь разлагается на последовательность элементарных актов различения
2. Каждый акт сопоставляется одной из четырёх базовых форм вокруг ∞
3. Форма заменяется соответствующим абитом
4. Результат — последовательность абитов, **неявно начинающаяся с ∞**

**Пример:** Связь `1` (единица смысла) сериализуется как `1`, но интерпретируется как `∞1`:
- `∞` — неявная точка начала
- `1` — запрос к форме `♂∞ -> ∞♀`

## Реализация в коде

### Парсер четверичных ачисел

```typescript
// src/core/quatAnum.ts

/**
 * Парсит содержимое .anum файла
 * @param content - содержимое файла
 * @returns массив AST узлов
 */
export function parseQuatAnumFile(content: string): ASTNode[]

/**
 * Конвертирует ачисло в формальную нотацию
 * @param content - строка из абитов
 * @returns строка формальной нотации
 */
export function quatAnumToFormal(content: string): string

/**
 * Валидирует структуру ачисла
 * @param content - строка из абитов
 * @returns результат валидации
 */
export function validateQuatAnum(content: string): ValidationResult
```

### Пример использования

```typescript
import { quatAnumToFormal, parseQuatAnumFile } from './core/quatAnum'

// Конвертация ачисла
const formal = quatAnumToFormal("01")
// Результат: "((∞♀ -> ♂∞) -> (♂∞ -> ∞♀))"

// Парсинг файла
const ast = parseQuatAnumFile(`
// Пример
1
0
[01]
`)
```

## Онтологическая чистота

| Аспект | Статус | Описание |
|--------|--------|----------|
| Нет внешних примитивов | ✅ | Абиты выводятся из форм связей вокруг ∞ |
| Нет разрыва знак↔связь | ✅ | Абит `[` не «обозначает» — он **есть** запрос к форме `♂∞` |
| Замкнутость системы | ✅ | Асети достаточно для резолюции всех запросов |
| Конструктивность | ✅ | Абиты конструируют связи через акты запроса |

Абиты — это **язык запросов к асети**, а не «кодировка» связей. Они работают как фильтры, выделяющие из океана связей те структуры, которые соответствуют четырём базовым формам вокруг акорня.
