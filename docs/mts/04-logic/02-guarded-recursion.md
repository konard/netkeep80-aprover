# Ограждённая рекурсия

> **Статус:** Рефакторинг завершён
> **Источник:** `06-guarded-recursion.md`
> **Этап:** 5.5

## Краткое описание

Ограждённая (guarded) рекурсия — это дисциплина рекурсивных определений в МТС. Рекурсивное определение допустимо **только и только тогда**, когда вводимая переменная встречается в правой части **строго под конструктором связи** `->`. Это правило является необходимым условием онтологической корректности определения.

---

## 1. Суть правила

### Формальное определение

В определении `s : F` рекурсивное упоминание `s` в `F` разрешено только под `->`.

### Почему `->` ограждает рекурсию

Конструктор `->` выполняет онтологическую функцию **порождения новой целостности** из двух компонентов. Когда рекурсивная переменная встречается под `->`, происходит следующее:

1. **Структурный отступ**: Каждое применение `->` создаёт новую связь, которая *структурно отличается* от своих компонентов. Рекурсивный вызов не тождественен исходной связи — он становится её *компонентом* в новой целостности.

2. **Прогресс в пространстве форм**: Последовательность развёртываний
   ```
   ♂x → (♂x -> x) → ((♂x -> x) -> x) → ...
   ```
   представляет не бесконечный процесс, а **единую форму связи** с самозамкнутым началом.

3. **Гарантия резолюции запроса**: В асети связей существует связь, форма которой удовлетворяет уравнению `y = y -> x`. Конструктор `->` обеспечивает, что это уравнение имеет решение.

---

## 2. Корректные и некорректные определения

| Корректно (ограждено `->`) | Некорректно (не ограждено) |
|---------------------------|----------------------------|
| `∞ : (∞ -> ∞)` | `∞ : ∞` |
| `♂x : (♂x -> x)` | `♂x : ♂x` |
| `x♀ : (x -> x♀)` | `x♀ : x♀` |

### Почему некорректные определения недопустимы

- `♂x : ♂x` — это не определение, а тавтология без конструктивного содержания
- Такое «определение» не задаёт паттерн различения формы — оно не позволяет отличить одну связь от другой
- Отсутствие конструктора `->` означает отсутствие акта связывания, а значит — отсутствие онтологического содержания

---

## 3. Фиксированная точка в асети связей

### Уникальность решения

В коиндуктивной онтологии МТС речь идёт о **единственной фиксированной точке**, которая существует благодаря структурной природе асети:

1. Асеть связей — это пространство всех возможных форм связей
2. Запрос по форме `♂x : (♂x -> x)` задаёт критерий отбора: «найти все связи `y`, для которых `y = y -> x`»
3. Аксиома тождественности гарантирует **единственность** такой связи

### Доказательство единственности

```
Если y₁ = (y₁ -> x) и y₂ = (y₂ -> x),
то по аксиоме тождественности: (y₁ -> x) = (y₂ -> x) → {y₁ = y₂, x = x}
Следовательно: y₁ = y₂.
```

Конструктор `->` в правой части обеспечивает, что уравнение имеет решение в асети — именно потому, что он *конструирует* связь, а не просто ссылается на неё.

---

## 4. Онтологическая интерпретация

Рекурсия в МТС — это не вычислительный процесс, а **свойство формы связи**:

| Аспект | Вычислительная рекурсия | Рекурсия в МТС |
|--------|-------------------------|----------------|
| Природа | Процесс развёртывания | Свойство формы |
| Результат | Вычисленное значение | Паттерн различения |
| Бесконечность | Бесконечный процесс | Единая замкнутая форма |

### Пример: самозамыкание начала

- Знак `♂x` не «вычисляется» через бесконечное развёртывание
- Знак `♂x` задаёт **паттерн различения**: запрос ко всем связям формы `y = y -> x`
- В асети связей существует ровно одна связь, удовлетворяющая этому паттерну — она и есть результат резолюции запроса

---

## 5. Проверка ограждённости

### Алгоритм проверки

1. Найти все вхождения определяемого имени в правой части определения
2. Для каждого вхождения проверить, находится ли оно под конструктором `->`
3. Если хотя бы одно вхождение не ограждено — определение некорректно

### Примеры проверки

```
// Корректно: ∞ ограждено под ->
∞ : (∞ -> ∞)
    ↑     ↑
    └──┬──┘
       оба под ->

// Некорректно: первое ∞ не под ->
∞ : ∞
    ↑
    не под ->
```

## Реализация в коде

```typescript
// src/core/normalizer.ts
export function checkGuardedRecursion(
  node: ASTNode,
  name: string,
  isGuarded: boolean = false
): boolean {
  // Проверка: если встретили определяемое имя, оно должно быть ограждено
  if (node.type === 'Identifier' && node.name === name) {
    return isGuarded;
  }

  // Link ограждает рекурсию
  if (node.type === 'Link') {
    return (
      checkGuardedRecursion(node.left, name, true) &&
      checkGuardedRecursion(node.right, name, true)
    );
  }

  // Другие узлы не ограждают
  // ...
}
```

Функция возвращает `true`, если все рекурсивные вхождения имени `name` в узле `node` находятся под конструктором `->`.

---

## Итог

Ограждённая рекурсия — это не техническое ограничение, а **онтологический принцип**:

> Рекурсивное определение должно конструировать новую целостность через акт связывания, а не просто повторять имя определяемой связи.

Конструктор `->` ограждает рекурсию, потому что он — единственный оператор, который *порождает существование* новой связи из компонентов. Именно это порождение гарантирует, что рекурсивный паттерн имеет резолюцию в асети связей как уникальная форма.
